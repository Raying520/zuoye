# 校园活动管理系统 — 用户访谈综合需求分析

> 分析对象：活动组织教师、学生参与者、系统管理员  
> 分析目的：将三类用户的访谈结论整合为统一的需求基线，明确 V1.0 / V2.0 / V3.0 的功能边界与验收标准。

---

## 一、访谈来源与核心视角

| 访谈对象 | 核心关注点 | 主要产出 |
|---|---|---|
| 活动组织教师 | 活动发布、报名审核、候补管理、活动编辑 | V2.0 核心需求 FR8–FR15 |
| 学生参与者 | 报名状态透明、候补可见、取消便捷、规则清晰 | V2.0 验证与界面优化输入 |
| 系统管理员 | 账号状态、角色权限、平台活动监管、操作留痕 | V3.0 候选需求 FR16–FR21 |

## 三、统一业务规则清单（BR1–BR16）

### V1.0 基础规则

| 编号 | 规则 | 说明 |
|---|---|---|
| BR1 | 仅教师可发布/管理活动 | 学生角色无发布/结束/取消权限 |
| BR2 | 仅 OPEN 状态可报名 | CLOSED/CANCELLED 活动禁止报名 |
| BR3 | 满员即止 | 已通过人数 ≥ 容量时，不开启候补则拒绝报名 |
| BR4 | 不可重复报名 | 同一学生对同一活动只能有一条有效报名记录 |
| BR5 | 结束/取消后停止报名 | 活动结束后状态流转终止 |

### V2.0 审核/候补规则

| 编号 | 规则 | 说明 |
|---|---|---|
| BR6 | 报名需经教师审核 | 若活动 requireAudit=true，报名后状态为 PENDING |
| BR7 | 通过审核不等于正式参加 | 教师通过后，若满员则进入 WAITING，否则 APPROVED |
| BR8 | 候补按时间顺序递补 | 取消释放名额时，waitingNo 最小者优先转正 |
| BR9 | 容量可动态调整 | 教师编辑活动时可调整容量；增加则递补，减少可能降级 |
| BR10 | 活动信息变更需同步 | 编辑后学生端展示最新信息 |
| BR11 | 取消报名释放名额 | 学生取消后，正式名额减 1，候补学生按顺序转正 |
| BR12 | 超过报名截止禁止报名 | 当前时间 > registrationDeadline 时禁止新报名 |

### V3.0 平台治理规则

| 编号 | 规则 | 说明 |
|---|---|---|
| BR13 | 管理员不替代教师处理报名 | 管理员只监管活动信息，不审核报名、不修改名单 |
| BR14 | 停用账号禁止登录 | 账号 status=DISABLED 时登录失败 |
| BR15 | 下架活动不可报名 | 平台状态 SUSPENDED 的活动对学生隐藏或禁用报名 |
| BR16 | 下架不删除数据 | 下架仅改变平台状态，不删除教师发布内容 |
| BR17 | 关键操作留痕 | 账号停用/启用、活动下架/恢复必须记录操作日志 |

## 四、统一数据状态定义

### 用户状态（V3.0 新增）

| 状态 | 含义 |
|---|---|
| ENABLED | 账号正常使用 |
| DISABLED | 账号被管理员停用 |

### 活动状态

| 状态 | 含义 | 控制方 |
|---|---|---|
| OPEN | 报名中 | 教师 |
| CLOSED | 已结束 | 教师 |
| CANCELLED | 已取消 | 教师 |
| NORMAL | 平台正常展示 | 管理员，默认 |
| FLAGGED | 被标记待整改 | 管理员 |
| SUSPENDED | 被管理员下架 | 管理员 |

> 说明：教师业务状态（OPEN/CLOSED/CANCELLED）与平台监管状态（NORMAL/FLAGGED/SUSPENDED）正交。管理员下架一个 OPEN 活动后，学生活动列表中不可见，但教师仍可查看自己的活动记录。

### 报名状态（V2.0 新增）

| 状态 | 含义 |
|---|---|
| PENDING | 审核中 |
| APPROVED | 已通过 / 已正式参加 |
| WAITING | 候补中 |
| REJECTED | 已拒绝 |

## 七、三访谈交叉验证结论

| 维度 | 教师 | 学生 | 管理员 | 一致性 |
|---|---|---|---|---|
| 报名审核 | 需要按条件筛选 | 希望标准与结果透明 | 不越权，由教师负责 | ✅ 一致 |
| 候补机制 | 保留候补名单，自动递补 | 愿意候补，需知道位置 | 不干预具体规则 | ✅ 一致 |
| 状态可见 | 教师要分清状态 | 学生要看懂自己状态 | 平台级状态需监管 | ✅ 一致 |
| 活动编辑 | 教师需要修改 | 希望信息准确 | 只监管，不直接修改 | ✅ 一致 |
| 取消报名 | 取消后释放给候补 | 愿意主动取消 | 不干预业务 | ✅ 一致 |
| 账号风控 | 未提及 | 未提及 | 需要启用/停用 | ⚠️ V3.0 新增 |
| 违规活动治理 | 未提及 | 未提及 | 需要下架/标记 | ⚠️ V3.0 新增 |

**结论**：教师与学生访谈共同定义了 V2.0 的核心方向，且已实现的 V2.0 代码基本覆盖双方诉求；管理员访谈暴露了平台治理缺口，构成 V3.0 的主要输入。V2.1 的界面优化是学生访谈的剩余补充，可快速提升体验。
