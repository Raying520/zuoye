# 校园活动管理系统 V1.0 — 验证记录

> 依据：`docs/工程意图.md` 第五节“完成依据”与 `docs/软件设计.md` 验收场景 S1–S6。
> 本记录由开发小组在本地运行后逐条填写“实际结果”与“是否通过”。

---

## 验证环境

| 项目 | 内容 |
|---|---|
| 操作系统 | Windows 10/11 |
| JDK 版本 | 17+ |
| 数据库 | H2（嵌入式，自动建表） |
| 运行方式 | IntelliJ IDEA 运行 `CampusActivityApplication` 或 `mvn spring-boot:run` |
| 访问地址 | http://localhost:8080 |
| 测试数据 | 虚构账号（如 teacher01 / student01），不使用真实个人信息 |

## S1 注册与角色分流

| 验证项 | 操作步骤 | 预期结果 | 实际结果 | 是否通过 |
|---|---|---|---|---|
| 学生注册 | 访问 `/register`，角色选“学生”，填写账号密码并提交 | 提示“注册成功，请登录”，跳转登录页 | | |
| 教师注册 | 访问 `/register`，角色选“教师”，填写账号密码并提交 | 提示“注册成功，请登录”，跳转登录页 | | |
| 学生登录 | 用学生账号登录 | 跳转 `/student/home`，看不到“发布新活动”入口 | | |
| 教师登录 | 用教师账号登录 | 跳转 `/teacher/home`，有“发布新活动”“管理我的活动”入口 | | |
| 未登录拦截 | 未登录直接访问 `/teacher/home` 或 `/student/home` | 被拦截回 `/login` | | |

## S2 发布与浏览

| 验证项 | 操作步骤 | 预期结果 | 实际结果 | 是否通过 |
|---|---|---|---|---|
| 教师发布活动 | 教师登录 → 发布新活动 → 填写标题/时间/地点/容量 → 提交 | 跳转教师工作台，活动成功保存 | | |
| 学生浏览列表 | 学生登录 → 进入 `/activities` | 看到教师刚发布的活动，按时间倒序 | | |

| 必填校验 | 发布时标题/时间/地点为空，或容量 < 1 | 页面提示相应错误，活动未保存 | | |

## S3 报名约束

| 验证项 | 操作步骤 | 预期结果 | 实际结果 | 是否通过 |
|---|---|---|---|---|
| 正常报名 | 学生对“报名中”活动点击“立即报名” | 提示“报名成功”，按钮变为“取消报名” | | |
| 重复报名拦截 | 再次点击同一活动的“立即报名” | 提示“你已经报名过该活动” | | |
| 满员拦截 | 多名学生报名直至人数 = 容量上限，新学生再报名 | 提示“活动名额已满”，无法报名 | | |
| 取消后再报 | 学生取消报名后，活动仍有名额，再次报名 | 报名成功 | | |
| 非学生拦截 | 教师访问报名接口 | 提示“只有学生可以报名活动” | | |

**结论：** ____________

## S5 活动管理
