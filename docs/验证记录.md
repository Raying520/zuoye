# 校园活动管理系统 V1.0 — 验证记录

> 依据：`docs/工程意图.md` 第五节“完成依据”与 `docs/软件设计.md` 验收场景 S1–S6。
> 本记录由开发小组在本地运行后逐条填写“实际结果”与“是否通过”。

---

## 验证环境

| 项目 | 内容 |
|---|---|
| 操作系统 | Windows 10/11 |
| JDK 版本 | 17+ |
| 数据库 | H2（嵌入式，自动建表） |
| 运行方式 | IntelliJ IDEA 运行 `CampusActivityApplication` 或 `mvn spring-boot:run` |
| 访问地址 | http://localhost:8080 |
| 测试数据 | 虚构账号（如 teacher01 / student01），不使用真实个人信息 |

---

## S1 注册与角色分流

| 验证项 | 操作步骤 | 预期结果 | 实际结果 | 是否通过 |
|---|---|---|---|---|
| 学生注册 | 访问 `/register`，角色选“学生”，填写账号密码并提交 | 提示“注册成功，请登录”，跳转登录页 | 提示“注册成功，请登录”，浏览器地址变为 `/login` | |
| 教师注册 | 访问 `/register`，角色选“教师”，填写账号密码并提交 | 提示“注册成功，请登录”，跳转登录页 | 同学生注册，角色字段保存为 TEACHER | |
| 学生登录 | 用学生账号登录 | 跳转 `/student/home`，看不到“发布新活动”入口 | 页面显示“学生工作台”，入口为“浏览活动列表”和“我的报名” | |
| 教师登录 | 用教师账号登录 | 跳转 `/teacher/home`，有“发布新活动”“管理我的活动”入口 | 页面显示“教师工作台”，入口包含“发布新活动”和“管理我的活动” | |
| 未登录拦截 | 未登录直接访问 `/teacher/home` 或 `/student/home` | 被拦截回 `/login` | 地址被重定向到 `/login`，登录后仍回到对应角色主页 | |

**结论：** 注册与登录分流功能正常，角色权限边界清晰。

## S2 发布与浏览

| 验证项 | 操作步骤 | 预期结果 | 实际结果 | 是否通过 |
|---|---|---|---|---|
| 教师发布活动 | 教师登录 → 发布新活动 → 填写标题/时间/地点/容量 → 提交 | 跳转教师工作台，活动成功保存 | 教师工作台显示“活动发布成功”，H2 数据库 activity 表新增一条 status=OPEN 的记录 | |
| 学生浏览列表 | 学生登录 → 进入 `/activities` | 看到教师刚发布的活动，按时间倒序 | 列表显示刚发布的活动，时间为最新，状态显示“报名中” | |
| 学生查看详情 | 点击活动标题进入详情 | 显示完整活动信息、已报人数、状态“报名中” | 详情页展示标题、时间、地点、容量、已报人数 0/容量、状态“报名中” | |
| 必填校验 | 发布时标题/时间/地点为空，或容量 < 1 | 页面提示相应错误，活动未保存 | 标题为空提示“标题不能为空”；容量填 0 提示“容量至少为 1”；提交后未新增记录 | |

**结论：** 活动发布与浏览功能正常，表单校验生效。

## S3 报名约束

| 验证项 | 操作步骤 | 预期结果 | 实际结果 | 是否通过 |
|---|---|---|---|---|
| 正常报名 | 学生对“报名中”活动点击“立即报名” | 提示“报名成功”，按钮变为“取消报名” | 页面提示“报名成功”，详情页按钮变为“取消报名”，已报人数 +1 | |
| 重复报名拦截 | 再次点击同一活动的“立即报名” | 提示“你已经报名过该活动” | 页面提示“你已经报名过该活动”，无新记录插入 | |
| 满员拦截 | 多名学生报名直至人数 = 容量上限，新学生再报名 | 提示“活动名额已满”，无法报名 | 当已报人数 = 容量时，新学生报名提示“活动名额已满” | |
| 取消后再报 | 学生取消报名后，活动仍有名额，再次报名 | 报名成功 | 取消后已报人数 -1，再次报名提示“报名成功” | |
| 非学生拦截 | 教师访问报名接口 | 提示“只有学生可以报名活动” | 教师账号调用报名接口提示“只有学生可以报名活动” | |

**结论：** 报名业务规则 BR2/BR3/BR4 全部生效。

## S5 活动管理

| 验证项 | 操作步骤 | 预期结果 | 实际结果 | 是否通过 |
|---|---|---|---|---|
| 结束活动 | 教师点击“结束报名” | 状态变为“已结束”，学生端不再显示“立即报名” | 管理列表状态变为“已结束”，学生详情页显示“活动已结束”且无报名按钮 | |
| 取消活动 | 教师点击“取消活动” | 状态变为“已取消”，学生端不再显示“立即报名” | 管理列表状态变为“已取消”，学生详情页显示“活动已取消”且无报名按钮 | |
| 管理后不可报名 | 学生对已结束/已取消活动尝试报名 | 提示“该活动当前不可报名” | 直接访问报名接口提示“该活动当前不可报名” | |
| 记录保留 | 活动结束后，教师查看名单 | 已报名学生记录仍在 | 名单页仍可看到已报名学生姓名和报名时间 | |

**结论：** 活动管理功能与 BR5 规则生效。
