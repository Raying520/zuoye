# 校园活动管理系统 V1.0 — 开发中遇到的问题与解决方案

> 本文档记录从仓库搭建到功能实现过程中遇到的代表性问题、原因分析与解决方案，供实验报告“总结与反思”部分参考。

---

## 问题 1：Gitee 推送时提示无权限

**现象**  
本地仓库初始化并提交后，执行 `git push` 报错：
```
ERROR: Permission to Raying1/trident-of-the-sea-god.git denied to variousa.
fatal: Could not read from remote repository.
```

**原因**  
本机生成的 SSH 公钥绑定到了 Gitee 账号 `variousa`，而仓库 `trident-of-the-sea-god` 的所有者是 `Raying1`。SSH 认证虽然成功，但认证通过的账号对目标仓库没有写入权限。

**解决方案**  
由仓库所有者 `Raying1` 在 Gitee 仓库设置中把 `variousa` 添加为仓库成员，并授予“可推送”权限。之后再次 `git push` 成功。

**经验**  
多人协作时要确认 SSH 密钥绑定的是哪个账号，仓库成员权限需要在仓库设置里单独配置，不能仅依赖密钥认证成功。

## 问题 2：H2 数据库保留字导致启动失败

**现象**  
第一次启动 Spring Boot 时，JPA 自动建表报错：
```
Syntax error in SQL statement ... expected "identifier"
```

**原因**  
`User` 实体的默认物理表名为 `user`，而 `user` 是 H2 数据库的保留字，直接执行 `CREATE TABLE user` 会语法错误。

**解决方案**  
在 `User` 实体上使用 `@Table(name = "app_user")`，将物理表名改为 `app_user`。该调整已登记到 `docs/软件设计.md` 第 6 节“设计调整记录”。

**经验**  
数据库表名应尽量避开各数据库的保留字；命名时给系统表加前缀（如 `app_`、`sys_`）是常见做法。

## 问题 3：日期时间输入框与 `LocalDateTime` 绑定失败

**现象**  
活动发布表单使用 `<input type="datetime-local">`，提交后 `activityTime` 字段校验失败，提示“活动时间不能为空”。

**原因**  
`datetime-local` 提交的值格式为 `2026-09-12T14:30`，而 Spring 默认不会自动把这种字符串转成 `LocalDateTime`。

**解决方案**  
在 `ActivityForm` 的 `activityTime` 字段上加 `@DateTimeFormat(pattern = "yyyy-MM-dd'T'HH:mm")`，显式指定格式，绑定成功。

**经验**  
前端日期/时间控件与后端 `java.time` 类型交互时，必须显式声明格式，不能依赖默认绑定。

## 问题 4：登录拦截器路径与页面链接不匹配

**现象**  
配置登录拦截器后，学生点击“浏览活动列表”可以正常访问，但某些链接仍被意外拦截或漏拦。

**原因**  
最初在 `WebConfig` 中配置拦截路径为 `/activity/**`，但项目里实际使用的是 `/activities/**`（复数形式）。路径不一致导致拦截规则不生效。

**解决方案**  
统一使用复数名词作为资源路径，将 `WebConfig` 中的拦截规则改为 `/activities/**` 和 `/enrollments/**`，与 Controller 的 `@RequestMapping` 和页面链接保持一致。

**经验**  
RESTful 风格路径应提前约定好单复数，避免拦截器、Controller、模板三方路径不一致。

## 问题 5：活动列表需要同时展示“已报名人数”

**现象**  
活动列表页只想展示活动基本信息，但需求要求显示当前已报名人数，而 `Activity` 实体本身没有该字段。

**原因**  
已报名人数来自 `enrollment` 表，需要关联查询或单独统计。若把该字段加到 `Activity` 实体中，会破坏数据模型纯净性。

**解决方案**  
创建 DTO `ActivityListItem`（包含 `Activity` 对象和 `enrolledCount` 统计值），并在 `ActivityService` 中新增 `findAllWithEnrollmentCount()` 方法，在查询活动后逐条统计报名人数。

**经验**  
展示层所需数据往往超出实体字段，应通过 DTO 组合，而不是修改实体或写复杂 SQL。

---

## 问题 6：教师查看报名名单时需要显示学生姓名

**现象**  
`Enrollment` 实体只保存了 `userId`，名单页面需要展示学生姓名，直接查 `Enrollment` 拿不到。

**原因**  
为了简化设计和避免 JPA 多表关联的复杂度，`Enrollment` 没有直接关联 `User` 实体，只保存了外键 ID。

**解决方案**  
在 `UserService` 中新增 `findNamesByIds(List<Long>)` 方法，先查名单得到所有 `userId`，再批量查询用户姓名，最后在 Controller 中组装成 `Map<Long, String>` 传给模板。

**经验**  
轻量级项目可以先用 ID 做逻辑关联，需要展示关联字段时再通过批量查询组装，避免过早引入复杂关联映射。

## 问题 7：本地 Java 项目无法直接部署为公开 URL

**现象**  
用户希望获得一个可登录的公网网址，但尝试使用 CloudStudio 部署时被告知其只支持纯静态网站。

**原因**  
本项目是 Spring Boot + H2 的后端应用，需要 Java 运行时和数据库支持，不属于静态 HTML/CSS/JS 站点。

**解决方案**  
给出两种备选方案：
1. **本地 + ngrok 隧道**：在本地启动项目后，用 ngrok 把 `localhost:8080` 暴露为临时公网 URL，适合演示。
2. **云服务器部署**：把项目打成 JAR 包上传到云服务器运行，获得持久公网 URL，但需要服务器资源和配置。

**经验**  
选择部署方案前要先判断项目类型。前端静态站点可直接使用静态托管；后端应用需要具备运行时的平台或服务器。

---

## 总体反思

1. **路径与命名规范很重要**：表名保留字、URL 单复数不一致等问题都源于命名不规范，前期统一约定可减少返工。
2. **DTO 是展示层的常用手段**：遇到“实体字段不够用”或“需要组合多表数据”时，优先使用 DTO 而不是修改实体。
3. **权限与认证要分开检查**：登录拦截器只保证“已登录”，具体业务权限（如是否活动发布者）需要在 Controller/Service 中二次校验。
4. **设计调整要及时登记**：H2 保留字问题发生后，立即登记到 `docs/软件设计.md` 的调整记录中，保证设计与代码一致。
